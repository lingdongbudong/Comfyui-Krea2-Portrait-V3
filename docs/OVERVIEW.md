## 0. 一句话定位

**纯本地、无大模型、模板填空式**的中文人像提示词随机生成器：
把 63 个随机池里的条目按固定 10 段模板装配成一段完整提示词，
配角色联动、内容分级、轴级权重、去重记忆与可复现种子。
**V3 是 V2 的减法重构** —— 不是又加一层，而是把 V1 的历史包袱整体卸掉、
再把 v3.11~v3.13 的能力补全。

## 2. 生成逻辑（详解）

```
generate()  节点层
 ├ 老参数兜底：模式=NSFW → 内容等级=explicit
 ├ 【v3.13】内容强度总旋钮 → 若选了档位则接管 等级/边界/NSFW强度
 ├ level → mode（sfw/suggestive→SFW；explicit 及以上→NSFW）
 ├ reroll ? seed=random : seed=输入值
 ├ 预设 overrides ─┐
 ├ 锁定字段 JSON ──┼→ locked{}    （锁定字段优先级高于预设）
 ├ 角色 → card → 特征推导 ─(联动强度按比例截取)→ 并入 locked + person_extra
 ├ 【v3.13】去重记忆 → avoid{字段:[最近取值]}
 └ V3.full_random(...)

full_random()  规则层
 ├ 应用 locked（含角色推导）
 ├ randomize_cloth_cat() / randomize_pose_cat()        分类级联
 ├ for sec in SECTIONS: for f in fields: randomize_field(f)
 │    └ 【v3.13】avoid 非空 或 温度≠1 → 走加权分支（否则原样分支）
 ├ enforce_conflicts()                                 冲突纠错（硬编码互斥规则）
 ├ fill_blanks() + enforce_conflicts()                 补空
 ├ apply_tattoo_weight(w)        ← 仅纹身开关开
 ├ apply_v311(人数/面积/百合)     ← 仅传参
 ├ apply_v312(边界/NSFW强度)      ← 仅传参
 └ build_prompt() → 10 段装配（+ off_items 关闭补充项）
     → 自检 → 超 600 字按 TRIM_ORDER 精简
```

## 3. 随机池内容

**63 个池 / 949 条**（`krea2_v3_rules.OPT`，读自 `presets/k2_v3_pools.json`）

- 主池 Top：scene 54 · prop 52 · shoes 34 · hairAcc 33 · socks 31 · tattoo 29 · accessory 27 · temperament 26
- **NSFW 专用池 8 个 / 125 条**：nsfwPose 20 · nsfwState 18 · nsfwProp 18 · nsfwBody 17 · nsfwMod 15 · nsfwShoes 14 · nsfwFabric 13 · nsfwChain 10
- **薄池（随机性会明显重复）**：age 9 · race 8 · skin 8 · lens 7 · clothCat 7 · pantyStyle 6 · leg 6

### 权重机制
- **轴级** 9 条：视角 / 景别 / 镜头 / 构图 / 构图位置 / 主光 / 场景 / 服装大类 / 姿态大类
- 公式：**本项命中概率 = 本项权重 ÷ 同轴全部选项权重之和**；0 = 剔除；范围 0–3，步进 0.05
- `WEIGHT_AXIS_DEFAULTS` 为空表 → 出厂全 1.0（等概率）

### 可关闭项
**28 项**补充项可关（device / ambient / film / cine / tattoo / hairAcc / makeupDetail /
smudge / nails / imperf1-2 / nsfw 系列 6 项 / cloth 系列 6 项 / shoes / socks /
accessory / prop / weather / styleTag）。核心项（镜头/人物/发型/服装主件/姿态/场景/构图）**关不掉**。

### ⚠️ 等级带事实
`LEVEL_BAND` 定义了六档目标区间，但 **V3 生成核心不引用它**（`strip_over_level()` 随
legacy 节点一起删了）。V3 里「内容等级」的真实作用只有：
① 切 SFW/NSFW 模式；② 给多人/百合/越界段挑分档。等级带仅用于面板文案展示。

## 4.3 v3.21 改动归类

一条需求：**修复「出图后 PNG 内嵌元数据里的提示词不完整」**。

### 症状

用户报障：看图工具里的「提示词」只显示成 `bl00m,`（那是 LoRA 触发词）。

### 根因（解剖那张图后确认）

**不是截断，是完整正文一个字都没进元数据。** 实测那张 `Krea2-文生图_00018_.png`：

```
PNG 里只有 2 个 tEXt 块 → prompt(API JSON) + workflow(UI JSON)
扫描全文：含「纵向构图」?  workflow=False  prompt=False
          含「中焦镜头」?  workflow=False  prompt=False
最长字符串是 LoRA 文本（406/850 字）
```

原因是这条链路里**所有承载文本的 widget 都被转成了输入连线**，`widgets_values` 全是空串：

| 节点 | 文本位 | 值从哪来 |
|---|---|---|
| `CLIPTextEncode#1133` | `[""]` | 连线 ← `StringConcatenate#1135` |
| `StringConcatenate#1135` | `["", "", ", "]` | `string_a` / `string_b` 都是连线 |
| `PrimitiveStringMultiline#1004` | `[""]` | 连线 ← `K2V3PromptEdit#1281` |
| `K2V3PromptEdit#1281` | `["", "直通", …]` | 连线 ← `K2V3GeneratorV2#1277` |
| `K2V3GeneratorV2#1277` | 43 个值，无一是正文 | 正文预览框是 `serialize:false` 的 DOM widget |

文本只在运行时内存里流动，**从未落到任何可序列化的位置**。看图工具拿不到，
就退而取了链上唯一"有字"的节点 —— LoRA 触发词 `bl00m` 加拼接分隔符 `", "`，
于是显示成 `bl00m,`（能逐字对上）。

### 修法：注入 extra_pnginfo

关键前提（读 ComfyUI 源码确认的）：
· `execution.py` 里 `extra_data.get('extra_pnginfo', None)` —— 同一次执行中
  **所有节点拿到的是同一个 dict 对象**；
· 原生 `SaveImage` 是在**自己执行的那一刻**才 `json.dumps(extra_pnginfo["workflow"])`。

所以插件节点只要在运行时把正文写进那个 dict，SaveImage 就照常写进 PNG：
**当次出图就带上、一根线都不用改、不碰第三方节点、完全不影响出图结果。**

新增 `k2_v3_pngmeta.py`：

| 函数 | 作用 |
|---|---|
| `inject_workflow_text()` | 写 UI 工作流（`workflow` 键）—— 三处：插件自己的节点、顺链的中间 widget、喂 positive 的 CLIPTextEncode |
| `inject_api_prompt()` | 写 API 图（`prompt` 键）—— **只写惰性键** |
| `inject_metadata()` | 节点侧唯一入口，**永不抛异常** |
| `merge_metadata_stats()` | 注入 + 往自检报告头 append 一行"元数据写没写进去" |
| ~~`build_parameters()`~~ | ~~拼 A1111 风格 `parameters`~~（v3.24 随保存节点一并移除） |
| `dump_workflow_prompt()` | 从 workflow 里读回提示词（校验脚本用） |

**两个必须记住的实现细节**：

1. ⚠️ **`widgets_values` 与 `widgets_values_named` 两份都要写**。ComfyUI 0.37 的前端

### ① 角色外观锁定（需求 3，也是本轮唯一碰到生成链路的改动）

用户的判断是对的 —— v3.19 之前**外观确实不一致**。实测：

| 场景 | v3.19 实测 |
|---|---|
| 角色联动开（默认） | 发色 `雾霾蓝`、发长 `过胸长发`、扎法、刘海固定；瞳色 `紫罗兰瞳` 固定 |
| | ⚠️ **卷度每次都变**：`直发柔顺` / `直发柔顺` / **`微卷蓬松`** |
| | ⚠️ 发态（11 档）也没锁 |
| 角色联动关 | 发色 / 发长 / 瞳色**全随机**（同一个甘雨：紫灰色 / 渐变染 / 深棕…） |
| 联动强度 < 1.0 | 按比例裁掉推导字段，发型可能被裁出去 |

三个根因分别对应三个修法：

| 根因 | 修法 |
|---|---|
| 推导只覆盖 发色/发长/扎法/刘海，**漏了卷度与发态** | 补齐 `hairCurl` / `hairState`；同时补 `hairColor`/`hairLen`/瞳色的缺标签兜底 |
| 整条推导挂在「角色联动」下面 | 抽出独立的 `CL.build_appearance_lock()`，**与联动解耦** |
| 「联动强度」会裁掉推导字段 | 合并发生在裁剪**之后**（顺序约束写进了代码注释） |

取值口径按"是否杜撰"排序，越靠前越可信：

| 项 | 有标签 | 无标签 |
|---|---|---|
| 发色 · 发长 · 卷度 · 发态 · 瞳色 | 用标签（覆盖率 91% / 88% / 2.5% / — / 86%） | 按**角色名 crc32 派生**从词库固定取一个 |
| 扎法 · 刘海 | 用标签（25% / 12%） | 取**中性值**（披散 / 无刘海）→ ④ 段**整句不写** |

- 扎法/刘海的无标签兜底刻意选"中性值"而不是随机：这两个是**显眼特征**，
  猜错（把披散猜成双马尾）比不写更糟；而"取中性值"在 ④ 段里的效果是
  `if htie and htie != "披散"` 直接跳过 → **既不杜撰、又确定**，两个原则都占住。
- 卷度/发态是**质感项**，抽到哪个都成立，所以用派生值换跨角色多样性。
- ⚠️ 派生种子必须用 `zlib.crc32`，不能用内置 `hash()` ——
  后者每进程带不同随机盐，表现是"重启一次外观就变了"。
- 全库覆盖率实测：发色 90.9% / 发长 87.7% / 瞳色 85.8% / 扎法 25.4% / 刘海 12.3% / 卷度 2.5%。
  也就是说**扎法/刘海/卷度三项绝大多数角色都走兜底**，兜底策略不是边角料。

控件与兼容：

- 新控件 `角色外观锁定`（BOOLEAN，默认 **True**），**追加在 optional 末尾**（第 33 个）。
- ⚠️ 空串/缺失必须归一成 True：老工作流的控件值缺失时 ComfyUI 传空串，
  而 `bool("")` 是 False → 不归一就会出现"新工作流一致、老工作流不一致"。
- 自检报告单列一行「角色外观锁定：…」，每项注明是**标签**推的还是**派生**补的。

## 6. 维护约定（改代码前必读）

1. **新增能力必须"默认不干预"**：参数为 `None`/默认值时**根本不调用**新方法。
   ⚠️ **"默认不干预"不等于"默认关"**：v3.20 的「角色外观锁定」默认 **True**
   （用户明确要求的外观一致性），但这个功能只在**选了角色**时才介入 ——
   没选角色时整条链路不启动，所以金标准 800/800 依旧逐字一致。
   判断标准是"**功能是否在这条用例的输入范围内生效**"，不是"开关是否为 False"。
   ⚠️ 新增**布尔型**控件的默认值若为 True，取值时必须把**空串/缺失也归一成 True**
   （ComfyUI 对老工作流缺失的控件传空串，`bool("")` 是 False）。
   这是金标准快照保持 800/800 的前提（v3.13 六个新控件全部遵守）。
2. **新增内容只能"独立追加段"**，不得插入既有 10 段之间。
3. **控件 / 输出端口一律追加在末尾**，不改既有名字与顺序。
4. **`WEIGHT_AXIS_FIELDS` 不能加新轴** —— 加了会让对应字段从 `rand_of` 切到
   `pick_weighted`，消耗随机序列，直接打破金标准快照。
5. **新功能做成独立节点 / 独立路由**，不合并进既有函数。
6. **源文件是 CRLF**（`.py` 实际是 LF，`.js` / `selftest.py` 是 CRLF）。
   用 Edit 工具改会自动跟随原文件，不会写坏；用 Python 脚本改写必须还原 `\r\n`。
7. ⚠️ **新增控件只能追加在 `optional` 末尾**。ComfyUI 按**位置**存 `widgets_values`，
   插在中间会让所有既有工作流的控件值整体错位（`selftest` 里有断言钉死这个顺序）。
8. ⚠️ **要退休某个控件时，只撤界面、不删控件位** —— 删中间任意一个都会让
   既有工作流的控件值整体错位。逻辑里不再读它即可（v3.18 退休了三个等级控件）。
9. ⚠️ **追加控件后必须确认节点有 `VALIDATE_INPUTS`**：老工作流的 `widgets_values`
   比现控件短，缺的位是空串，FLOAT 控件收到空串会被 ComfyUI 判非法 →
   **整个工作流跑不起来**（v3.17 踩过，v3.18 用 `VALIDATE_INPUTS` 兜住）。
10. ⚠️ **只要动过「控件个数」或「输出端口的顺序 / 个数」，就必须跑一次工作流迁移脚本**
    （模板见 `tools/fix_workflows_v319.py`）：连线的 slot 索引和 `widgets_values`
    都是按位置存的，不迁移就会出现"能打开、但线接错 / 新控件继承上古垃圾值"。
    迁移脚本必须**幂等**（跑两遍结果一样），写完后用 `--dry` 复检一次。
11. 组件类的 tooltip **尽量自动生成**（遍历内容表），别手写 —— 手写的清单在扩项时必漏。
12. ⚠️ **改「元数据」相关逻辑前先读 `k2_v3_pngmeta.py` 的文件头**：
    `workflow`（UI JSON）只用于展示、随便写；`prompt`（API JSON）**是执行用的图**，
    改它已声明的输入会真的改变执行结果 —— 所以只写惰性键。
    另外前端有 `widgets_values` **和** `widgets_values_named` 两份，只改一份 = 两套值不一致。
13. ⚠️ **改署名文案时，六处落点必须逐字一致** —— 自测里有一条断言钉着这个
    （忽略折行与代码层拼接符后比对）。另外：用户给的文案里的标点（全角/半角冒号）
    要**先确认再落笔**，别照着「看着像半角」直接抄。
14. 每轮必跑上面第 5 节那几条命令（全绿才算改完）。

## 7. 升级空间与扩展方向（推断）

### 7.1 已经做完的"减法"

结构收敛已经完成：V3 = 14 个运行时文件 / 290 KB，只剩一条主线。
**这一段不再有优化空间**，剩下的都是"往上加"。

### 7.2 数据层：还有明确扩容空间 ⭐ 性价比最高

| 方向 | 现状 | 可做 |
|---|---|---|
| 角色池 | 2130 人，中文名覆盖 **21.5%**（459/2130） | 补人工译名表（成本低、收益直接可见）；四款游戏 40/18/55/34，safebooru 上 HSR 仍有 92 个候选标签可挖 |
| 薄池 | age 9 / race 8 / skin 8 / lens 7 / clothCat 7 | 这几个维度随机性会明显重复，扩容后"换个样子"的体感提升最明显 |
| 新维度 | 目前 69 个字段 | 可加：天气细分、时间段、镜面/反光、肤质细节、配饰成套 |

**推断**：数据层是当前**投入产出比最高**的方向 —— 不改一行逻辑，纯扩池即可提升出图多样性。

### 7.3 可控性层：下一步该做"配置能力"

| 方向 | 为什么 |
|---|---|
| **去重记忆按段落独立设置**（现在只有一个全局深度） | 场景/道具最容易重复，人物特征反而不需要去重 |
| **字段级黑名单**（比"权重设 0"更直观） | 已有逐项开关，但只覆盖 28 个补充项；核心字段的选项还不能拉黑 |
| **方案分组 / 标签** | 方案多了以后需要分类检索 |
| **A/B 对比视图** | 同种子改一个参数，左右并排出两条 |
| **组合数实时显示在面板上**（现在只在报告里） | 让人直观看到"改这个参数会不会让池子变小" |

### 7.4 随机性层：已有基础，可继续加深

已完成：去重记忆、温度、批量候选。
可继续：
- **按池分别设温度 / 记忆深度**（不同维度重复的容忍度不一样）
- **用户自定义互斥规则**（`enforce_conflicts()` 目前是硬编码的）
- **覆盖率统计**：跑 N 次统计各池实际命中的分布，找出"看起来大其实抽不到"的池

### 7.5 输出层：往流水线走

出题节点已能给出 `提示词 / 负面词 / 种子 / 元数据 / 候选列表`，
配合「预览编辑」与**原生 SaveImage**（出题节点会在运行时把正文注入 `extra_pnginfo`），已具备搭
**"批量出题 → 批量出图 → 自动写元数据 → 按元数据筛选"** 流水线的条件。
缺的是：**一次跑 N 个种子并自动命名输出** 的批处理节点。

### 7.6 架构层：还能再做一次减法

`k2_v3_node.py`（42 KB）目前一个文件里塞了：控件定义 + 出题逻辑 + 12 条路由 + 存储调用。
如果再长下去，建议拆成 `k2_v3_node.py`（纯控件+出题）/ `k2_v3_routes.py`（路由）。
**现在还不痛，先记着。**

### 7.7 明确不建议做的

- ❌ **接入大模型润色**：会破坏"逐字可复现"，且引入网络依赖。若真要做，
  必须是**默认关闭的独立节点**，把润色结果写回提示词，而不是隐式插入。
- ❌ **恢复 V1 的层级带过滤**：V3 里等级带本来就不生效，这是历史遗留的
  "看起来有其实没有"的逻辑，不该复活。
- ❌ **改节点内部 ID**：会让所有既有工作流打不开，收益仅是名字好看。

### 7.8 我的排序建议

1. **薄池扩容 + 中文名补齐**（纯数据，零风险，体感直接）
2. **去重记忆分段化 + 核心字段黑名单**（继续提升可控性）
3. **批处理出图节点**（把能力接成流水线）
4. **`k2_v3_node.py` 拆分**（等它再长到痛为止）
