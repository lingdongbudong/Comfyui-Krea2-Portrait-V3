## 一、安装与配置

### 1.1 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| ComfyUI | **0.3.x 及以上** | 在 0.37.4 上验证 |
| Python | **3.10+** | 在 3.12.10 上验证 |
| 额外 pip 依赖 | **无** | 只用 Python 标准库 + ComfyUI 本体 |
| 显卡 / 模型 | **不需要** | 只出提示词时，没有模型、断网、显卡满载都能跑 |
| 磁盘 | 约 3 MB | 角色缩略图（可选，约 40 MB）需要自行抓取 |

### 1.2 安装步骤

**方式 A：git clone**

```bash
cd <你的ComfyUI根目录>/custom_nodes
git clone <本仓库地址> Comfyui-Krea2-Portrait-V3
```

**方式 B：下载 ZIP 解压**

把压缩包解压到 `<你的ComfyUI根目录>/custom_nodes/` 下，**确认最终目录结构是**：

```
custom_nodes/
└── Comfyui-Krea2-Portrait-V3/
    ├── __init__.py
    ├── k2_v3_node.py
    ├── js/
    └── presets/
```

⚠️ 常见错误：解压后多套了一层（如 `custom_nodes/Comfyui-Krea2-Portrait-V3-main/Comfyui-Krea2-Portrait-V3/`），
ComfyUI 就找不到插件。目录名**必须**是 `Comfyui-Krea2-Portrait-V3`。

**然后重启 ComfyUI**（关掉进程重新启动，不是刷新网页）。

### 1.3 验证安装是否成功

**第 1 步：节点列表**

在画布上右键（或双击空白处）→ 搜索 `K2` 或 `Krea2-Portrait-V3`，
应该能看到 **3 个节点**：

| 显示名 | 内部 ID |
|---|---|
| ★ Krea2-Portrait-V3 · 随机出题 | `K2V3GeneratorV2` |
| ★ Krea2-Portrait-V3 · 提示词预览与编辑 | `K2V3PromptEdit` |
| ★ Krea2-Portrait-V3 · 提示词导出（txt / md / json） | `K2V3PromptExport` |

**第 2 步：跑一次「完全不出图」的最小链路**

打开 `workflows/Krea2-Portrait-V3_独立提示词输出.json` → 点 **Queue**。
面板下方出现一段中文提示词、`output/K2V3_prompts/` 下出现一个 `.txt`，即安装成功。

**第 3 步（可选）：命令行自检**

在插件目录下执行：

```bash
python - <<'PY'
import sys, importlib.util
spec = importlib.util.spec_from_file_location('p', '__init__.py',
                                              submodule_search_locations=['.'])
pkg = importlib.util.module_from_spec(spec); sys.modules['p'] = pkg
spec.loader.exec_module(pkg)
print("版本:", pkg.__version__)
print("节点:", sorted(pkg.NODE_CLASS_MAPPINGS))
g = pkg.NODE_CLASS_MAPPINGS["K2V3GeneratorV2"].INPUT_TYPES()
print("控件: %d 必填 + %d 可选" % (len(g["required"]), len(g["optional"])))
r = pkg.NODE_CLASS_MAPPINGS["K2V3GeneratorV2"]().generate(
    内容强度="全年龄", 人物数量="单人", 角色="自动", 随机种子=1, 每次运行重随机=False)
print("出题成功:", len(r["result"][0]), "字")
PY
```

期望输出：版本 `3.24.1`、3 个节点、`5 必填 + 40 可选`、出题成功约 600 字。
能跑出这段就说明**词库、角色池、生成逻辑全部就位**。

> ⚠️ 装好后第一次用，建议**刷新一次浏览器页面** —— 否则插件面板可能是缓存里的旧版本。

### 1.4 建议的初始配置

装好后先别急着调参数，**按这个顺序动三个地方**就能出有用的词：

1. **设置面板 →「① 内容强度」**：先选「全年龄」跑几条看看手感；
2. **主界面 →「👤 角色」**：搜一个你熟悉的角色点选（比「自动」有针对性得多）；
3. **设置面板 →「⑥ 人物与角色」**：确认「角色外观锁定」是开着的（默认开）——
   这样同一角色反复出题时发型、瞳色不会乱变。

其余的权重、去重、温度等，等你有明确诉求时再动。

### 1.5 数据文件与目录

**随仓库提供**（运行时必需）：

| 路径 | 作用 |
|---|---|
| `presets/k2_v3_pools.json` | **主词库**：63 个池 / 949 条（从 HTML 脚本导出，**勿手改**） |
| `presets/k2_v3_extra_pools.json` | 附加池：纹身面积 / 人数 / NSFW 内容项与权重基准 / 多人·百合·越界场景 |
| `presets/character_pool.json` | **角色池**：2165 位（含作品名、标签） |
| `presets/user_pools.json` | 用户自定义池（留空也能跑） |

**本机自动生成**（不在仓库内，删了会自动重建）：

| 路径 | 作用 |
|---|---|
| `user_data/history.json` | 出题历史（面板「历史」页签） |
| `user_data/recent.json` | 最近记录 |
| `user_data/k2v3_presets.json` | 「🗂 方案」保存的配置 |
| `thumbs/` | 角色缩略图缓存（**可选**，见下） |

**关于角色缩略图**：仓库不含 `thumbs/`（约 40 MB / 2000 张）。
没有它时角色图鉴会**退回首字色块**，**不影响出题** —— 出题只用角色名，不用图片。
需要图鉴显示头像时自行抓取（脚本在维护者分支/历史提交中，需遵守图源站点的使用条款）。

### 1.6 升级与卸载

**升级**：在插件目录执行 `git pull`，然后重启 ComfyUI。
没有 git 的，重新下载 ZIP 覆盖即可（`user_data/` 是本机数据，覆盖时会保留）。

**卸载**：删掉 `custom_nodes/Comfyui-Krea2-Portrait-V3/` 整个目录，重启 ComfyUI。
不会影响任何其它插件；既有工作流里若有本插件节点，重新打开时会显示为缺失节点（红色），
删掉它们即可。

## 二、界面总览

选中「随机出题」节点后，**在画布上直接看到的是自定义面板**（不是原生控件行）。

主界面自上而下：

```
① 免责声明横幅（默认展开；「收起」只留一行窄条，右侧常驻「📜 查看全文」）
② 快捷操作行（🎲 换一条 · 🗂 方案 · 📜 免责声明 · ⚙️ 设置 · 👤 角色 …）
③ 状态摘要（当前等级 / 人物 / 角色 / 字数 …）
④ 预览文本框 + 复制条（📋 复制提示词）
⑤ 自检报告框（每次出题后的可读报告）
```

真正的设定项收在「**⚙️ 设置**」弹窗里，**七个功能区，每个都能单独折叠**
（点标题行 ▶/▼，折叠状态会记住）：

| 区 | 名称 | 什么时候动它 |
|---|---|---|
| ① | 内容强度 | 决定"多露骨"，**唯一**的等级控制项 |
| ② | 随机性质量 | 感觉老是抽到重复场景时 |
| ③ | 逐项开关 | 想去掉某一类补充项（鞋、袜、天气…）时 |
| ④ | 字段微调 | 想把某几个字段钉死时 |
| ⑤ | 权重 | 想提高某类镜头 / 场景 / 服装出现率时 |
| ⑤b | 外观细节权重 | 想控制鞋履种类与水波反光时 |
| ⑥ | 人物与角色 | 单人 / 双人 / 指定角色 / 外观锁定 |
| ⑦ | NSFW 内容权重 | 只影响 NSFW 各项的相对占比 |

> 编号里有「⑤b」是因为这一组是后来插入的，**刻意不改动原有 ①–⑦ 的编号**，
> 免得跟旧文档、旧截图对不上。

**免责声明的三个入口**（任意一个都能看到全文，不会丢）：
面板顶部横幅 · 快捷操作行「📜 免责声明」 · 「⚙️ 设置」面板顶部。

## 三、主要功能与参数说明

### 3.1 出题节点 · 必填输入（5 个）

| 控件 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `内容等级` | COMBO | `sfw` | **已退休**。等级控制已收敛到「内容强度」；此值仅在「内容强度」被设为旧值「手动（分别设置）」时作为兼容兜底被读取，其它情况不参与。 |
| `角色` | COMBO | `自动` | 绑定角色。可打开面板「👤 角色图鉴」浏览缩略图点选。选「自动」时每次随机一个角色。 |
| `角色联动` | BOOLEAN | ✅ 开 | 按所选角色的特征（服装大类 / 场景 / 气质 / 体型）组织内容；角色没有的特征仍交给随机，**不会凭空杜撰**。关闭则完全随机（仅保留角色名）。 |
| `每次运行重随机` | BOOLEAN | ✅ 开 | 每次 Queue 都重新随机出一条新提示词（内部靠 `IS_CHANGED` 绕过 ComfyUI 的结果缓存）。要复现就关掉它。 |
| `随机种子` | INT | 0 | 本次实际使用的种子（**输出性质**）。关掉重随机后改它可精确复现某一条。 |

> ⚠️ 「角色」与「角色联动」是两件事：前者决定**写谁**，后者决定**要不要按这个人的特征写**。

### 3.3 出题节点的 6 个输出端口

| # | 端口 | 内容 | 典型接法 |
|---|---|---|---|
| 0 | `提示词` | 完整正文（中文自然语言，单人 ≤600 字 / 双人 ≤1000 字） | → CLIP Text Encode 的 `positive` |
| 1 | `自检报告` | 本次的可读报告（等级 / 联动 / 权重 / 冲突纠错 / 字数 / 外观锁定来源） | 接任何文本预览节点，或不用 |
| 2 | `槽位JSON` | 本次各字段的结构化取值（69 个字段） | 调试与对账 |
| 3 | `随机种子` | 本次实际使用的种子 | 可用于复现 |
| 4 | `元数据JSON` | 种子 / 完整提示词 / 等级 / 角色 / 人数 / 纹身面积 / 百合 / 插件名 | 落到图片元数据 |
| 5 | `候选列表` | 批次数 > 1 时，第 2 条及以后的候选 | 挑备用词 |

> ⚠️ 端口是**按索引**连线的：v3.19 删掉「负面提示词」端口时，后面端口整体前移了一位。
> 现在这个顺序已稳定，升到 3.24 不需要调整连线。

**关于 PNG 元数据**：出题节点与提示词编辑节点会在运行时把正文注入
`extra_pnginfo`，所以**用原生 `SaveImage` 出图时，PNG 元数据里会带上完整提示词** ——
不需要额外节点，也不用改你的工作流。

### 3.4 设置面板：七个功能区逐项说明

#### ① 内容强度 —— NSFW 等级的唯一控制项

五档，选哪档就严格按哪档抽卡：

| 内容强度 | 模式 | 可出现的内容 |
|---|---|---|
| 全年龄 | SFW | 只写 SFW 池，不写 ⑧ 姿态段，**无性行为** |
| 暗示 | SFW | 同上，措辞更暧昧 |
| 露骨 | NSFW | 展示生殖器 · 自慰 · 手交 · 乳交 · 足交 · 其它 |
| 强露骨 | NSFW | 上面六项 + 口交 · 深喉 · 束缚·捆绑 · 潮吹·失禁 |
| 极端 | NSFW | 上面十项 + 性交 · 肛交 · 多人，并自动带**越界描写** |

> v3.18 之前能改"多露骨"的控件一共有四个（内容等级 / 内容边界 / NSFW开关+强度 / 内容强度），
> 互相打架。现在撤掉后三个，只留这一个。
> **控件位保留在原处不删**（ComfyUI 按位置存值，删中间任意一个会让旧工作流的控件值整体错位），
> 只是界面上看不到。
> 老工作流里若「内容强度」是旧值「手动（分别设置）」，会自动回落到旧「内容等级」的值，**不会静默掉档**。

#### ② 随机性质量

| 项 | 默认 | 作用 |
|---|---|---|
| `去重记忆` | 0（关） | 记住最近 N 次用过的取值并降权，避免连着抽到同一场景 |
| `多样性温度` | 1.0 | >1 更极端（冷门取值更容易中）；<1 更保守；1.0 = 原始分布 |
| `联动强度` | 1.0 | 角色推导字段的**采用比例**（1.0 = 全采用；0.5 = 只采用一半） |
| `批次数` | 1 | 一次出 N 条候选（第 1 条仍是主输出，其余进「候选列表」端口） |

**什么时候调**：觉得"翻来覆去就那几套" → 把「去重记忆」调到 5–10；
觉得"太出格" → 把「多样性温度」降到 0.8 左右。

#### ③ 逐项开关

只有 **28 个「补充项」**能被关掉；镜头 / 人物 / 发型 / 服装主件 / 姿态 / 场景 / 构图
是**核心项，关不掉**。

| 分段 | 可关闭的项（id） | 数量 |
|---|---|---|
| 镜头 | `device`（器材） | 1 |
| 光线 | `ambient`（环境光） | 1 |
| 发型 | `hairAcc`（发饰） | 1 |
| 妆容 | `makeupDetail`（妆容细节） · `smudge`（晕染） · `nails`（指甲） | 3 |
| 服装 | `clothBottom` · `clothMat` · `clothPattern` · `clothDeco` · `clothLayer` · `shoes` · `socks` · `accessory` · `nsfwMod` · `nsfwFabric` · `nsfwBody` · `nsfwProp` · `nsfwShoes` | 13 |
| 姿态 | `nsfwChain` | 1 |
| 背景 | `prop`（道具） · `weather`（天气） | 2 |
| 构图 | `styleTag`（风格标签） | 1 |
| 附加 | `film`（胶片感） · `cine`（电影感） · `imperf1` · `imperf2`（瑕疵） · `tattoo`（纹身） | 5 |

**怎么用**：面板「③ 逐项开关」里点选，或直接往 `关闭可选项` 控件里填 id，
多个用英文逗号分隔（如 `prop,weather,socks`）。留空 = 一项都不关。

#### ④ 字段微调 —— 点选 / 手输 / 批量锁定

把某个字段钉成指定值，随机时跳过它，其余字段照常随机。
**可锁字段 53 个**（全库共 69 个字段）。一张表按段落折成
「① 镜头 … ⑪ 附加」十一个折叠区（默认展开人物与发型两组，搜索时全展开）。

**哪些字段不能锁**（都有明确理由）：

| 类别 | 字段 | 为什么 |
|---|---|---|
| 动态字段（7） | `clothSubCat` `clothItem` `clothBottom` `poseSubCat` `pose` `imperf1` `imperf2` | 候选值取决于上级分类，没有静态列表可点 |
| NSFW 档字段（8） | `nsfwState` `nsfwMod` `nsfwFabric` `nsfwBody` `nsfwProp` `nsfwShoes` `nsfwPose` `nsfwChain` | 取值属于「内容强度」链路，单独锁会把 SFW 提示词污染成 NSFW |
| `stylePreset`（1） | 风格预设 | **锁了等于没锁**：预设只在"随机抽到它"时生效，被锁的字段会跳过随机 |

**六个动作**：

| 动作 | 怎么做 |
|---|---|
| **点选候选值** | 点字段行 → 上方弹出该字段的**全部候选值**，点哪个锁哪个 |
| **手输自定义值** | 候选区底部输入框写任意文本（可以写词库外的描述），点「锁定为这个值」 |
| **搜索字段** | 顶部搜索框按中文名 / 英文 id / 已锁定值过滤 |
| **🔒 锁定当前整套值** | 把最近一次生成结果里**所有**字段取值一次性锁死（= 完全复现这一套） |
| **🎲 重摇全部已锁** | 锁定项的个数不变，每项各换一个新候选取值 |
| **🗑 清空全部锁定** | 一次撤掉所有锁定 |

字段行上会同时显示「本次实际值」（来自最近一次生成的槽位表）与「🔒 锁定值」，
两者不一样时一眼就能看出来。

#### ⑤ 权重（轴级权重）

命中概率 = **该选项权重 ÷ 同轴全部选项权重之和**。

`0` = 永不出现；整轴同乘一个倍数**不改变分布**（因为会归一化）。

可加权的 9 个轴：

| 轴 | 字段 | 选项数 |
|---|---|---|
| 视角 | `viewpoint` | 13 |
| 景别 | `shotSize` | 11 |
| 镜头 | `lens` | 7 |
| 构图 | `comp` | 13 |
| 构图位置 | `compPos` | 6 |
| 主光 | `mainLight` | 12 |
| 场景 | `scene` | 54 |
| 服装大类 | `clothCat` | 7 |
| 姿态大类 | `poseCat` | 4 |

也可以直接用 `权重覆盖` 控件写文本，如 `视角:俯视=3`。

#### ⑤b 外观细节权重

| 控件 | 默认 | 范围 | 作用 |
|---|---|---|---|
| `高跟鞋权重` `靴子权重` `运动鞋权重` `凉鞋权重` `皮鞋权重` `赤脚权重` | 1.00 | 0.00 – 3.00 | 控制**鞋履种类**的抽中率 |
| `水面反光权重` | 1.00 | 0.00 – 3.00 | 控制环境光里「水面反光（水面波光倒映在皮肤上，光影流转）」的出现率 |

规则：某款鞋的权重 = **它所属种类**的权重；「不使用（不写鞋履）」**恒为 1.00**（不受影响）。
全 1.00 时**完全不干预**。

**例**：想让画面里只出现靴子 → 把另外五种都设成 `0`；
完全不想要水面反光 → 把 `水面反光权重` 设成 `0`。

#### ⑥ 人物与角色（含外观锁定）

| 项 | 说明 |
|---|---|
| 👤 单人 / 👥 双人 | 单人 = 保证画面里只有一个人（连性行为内容也只抽"单人可见"的条目）；双人 = 提示词**最前面**先交代两人互动的详细内容 |
| 🌸 百合 | 双人 + NSFW 档**自动**走百合；这个开关用来在 SFW 档也强制百合 |
| 角色 A / 角色 B | 双人可分别指定两位角色，两位都会**点名**写进互动段（不会出现「她…她」的指代歧义） |
| 🔒 **角色外观锁定** | **默认开**，见下 |
| 字数上限 | 双人 ≤ **1000 字**，单人 ≤ **600 字** |

**角色外观锁定锁什么**：指定角色后，以下七项**每次都一样**（换种子、重复 Queue、重启 ComfyUI 都不变）：

| 锁的项 | 来源 |
|---|---|
| 发色 · 发长 | 角色标签（实测覆盖率 91% / 88%） |
| 卷度 · 发态 | 角色标签 → 无标签时按**角色名派生**固定取一个 |
| 扎法 · 刘海 | 角色标签 → 无标签时取**中性值**（= 正文里不写这两句，不杜撰） |
| 瞳孔颜色 | 角色标签（覆盖 86%）→ 无标签时按角色名派生固定取一个 |

「角色名派生」= 用角色英文名的 `crc32` 当随机种子从词库取一个值 ——
同一角色永远同一个结果，不同角色之间仍有变化。

**两个容易混的开关**：

| 开关 | 管什么 | 关掉的影响 |
|---|---|---|
| 角色**外观**锁定（默认开） | 只管"这个人长什么样"（上表七项） | 发色 / 发型 / 瞳色每次重随都会变 |
| 角色**联动**（默认开） | 服装大类 / 场景 / 气质 / 体型 | 服装与场景回到随机；外观仍由外观锁定负责 |

两者**互相独立**；「联动强度 < 1.0」只影响联动那部分，**不会**削掉外观锁定。
「角色」为「自动」时外观锁定不生效（随机角色无所谓一致）。
自检报告里会单列一行「角色外观锁定：发色→…（标签）」，
每项后面都注明是**标签**推的还是**派生**补的，便于核对。

**不锁**：发饰、妆容、服装、场景、姿态 —— 它们是"这一张的风格"，不是"这个人是谁"。

#### ⑦ NSFW 内容权重（设置页最底部）

13 个滑块，只决定"在当前档位够得着的项里谁更容易中"：
**概率 = 该项权重 ÷ 当前档位下全部可用项的权重之和**。

`0` = 该项永不出现；`1.00` = 标准比例；上限 `5.00` = 大幅提高占比。

| 内容项 | 最低档位 | 单人模式下 |
|---|---|---|
| 展示生殖器 · 自慰 · 手交 · 乳交 · 足交 · 其它 | 露骨 | 手交 / 乳交 / 足交 **自动排除**（必须有第二人） |
| 口交 · 深喉 · 束缚·捆绑 · 潮吹·失禁 | 强露骨 | 深喉 **自动排除** |
| 性交 · 肛交 · 多人 | 极端 | 多人 **自动排除** |

**「🔗 内容权重 · 跟随等级」开关**（默认关）：开启后 13 项权重不再由滑块决定，
而是按当前档位自动算一套基准 —— 档位越高越偏向该档的招牌内容
（**露骨偏自慰 → 强露骨偏口交 → 极端偏性交**）。
开启时滑块置灰只读并显示基准值；关掉立刻回到手动值（**手动值不会被覆盖**）。

> **等级先筛范围、权重再定概率** —— 这两步是分开的：
> 权重调到 5.00 也不能让「性交」在「露骨」档出现，因为那一档根本够不着它。

### 3.5 提示词预览与编辑节点

接在出题节点之后，把上游生成的完整提示词**原样展示**在一个可读的大文本框里。

| 控件 | 默认 | 说明 |
|---|---|---|
| `提示词` | 空 | 上游「提示词」输出接进来 |
| `编辑模式` | **直通（不修改）** | 直通时输出与输入**逐字一致**（不做 trim、不做任何加工） |
| `手动文本` | 空 | 「覆盖为手动文本」模式下用它替换 |
| `查找替换` | 空 | 形如 `旧=>新`，支持多个用 `;` 分隔 |
| `前缀` / `后缀` | 空 | 「追加前后缀」模式下在首尾添加 |
| `去除首尾空白` | 关 | **只对非直通输出生效**（直通永远保证逐字一致） |

输出两个端口：`提示词`、`编辑报告`（说明这次到底改了什么）。

> 老工作流把本节点串进来，行为完全不变 —— 因为默认是直通。

### 3.6 提示词导出节点

**纯文本输出端点**（`OUTPUT_NODE = True`）。接上它以后，
ComfyUI 只执行到这条链，**后面的 CLIPTextEncode / KSampler / VAE / SaveImage 都不会被执行**。

| 控件 | 默认 | 说明 |
|---|---|---|
| `提示词` | 空 | 要落盘的内容 |
| `输出格式` | `txt（只有提示词正文）` | txt / md / json |
| `保存子目录` | `K2V3_prompts` | 相对 `ComfyUI/output/` |
| `文件名前缀` | `K2V3` | 最终形如 `K2V3_00001_.txt` |

输出两个端口：`文件路径`、`提示词`（原样透传，方便同时接别的地方）。

**典型用途**：批量攒提示词后拿到别的工具里用；归档；把「报告 / 槽位JSON」一起存档。

### 3.7 三类权重到底有什么区别

| 权重 | 作用对象 | 取值范围 | 分母是谁 | 入口 |
|---|---|---|---|---|
| **轴级权重** | 9 个「大类」字段的**选项** | 0 – 3（文本式无硬上限） | 同一轴内全部选项 | 设置「⑤ 权重」/ `权重覆盖` |
| **NSFW 内容项权重** | 13 个**内容项** | 0 – 5.00 | 当前**档位下可用**的项 | 设置「⑦ NSFW 内容权重」 |
| **外观细节权重** | 6 类鞋履 + 水面反光 | 0 – 3.00 | 该字段全部候选项 | 设置「⑤b 外观细节权重」 |

三者共同点：**都是加权抽卡（权重 ÷ 同字段权重和），设 0 即永不出现**。
不同点：分母范围不同 —— 内容项权重只在"当前档位够得着"的项之间归一，
所以调高它不会让越界内容突破档位限制。

## 四、典型使用示例

### 示例 1：只要提示词（不装任何模型）

**目的**：快速验证安装、批量攒词、给写作/绘画找素材。

1. 打开 `workflows/Krea2-Portrait-V3_独立提示词输出.json`；
2. 设置面板「① 内容强度」选「全年龄」，「⑥ 人物与角色」里挑一个角色；
3. 点 **Queue** → 面板下方出现提示词，`output/K2V3_prompts/` 下出现 `K2V3_00001_.txt`；
4. 再点一次 Queue 换一条。

**关键点**：这条链完全不出图，**不需要任何模型**，断网也能跑。

### 示例 2：接进你现有的出图链路

**目的**：把插件生成的词喂给你原来的工作流。

1. 把「随机出题」拖进画布，输出的 `提示词`（第 1 个端口）接到 CLIP Text Encode 的 `positive`；
2. 如果你的链路里还有 LoRA 触发词拼接（`StringConcatenate` 之类），
   把拼接结果接到 CLIPTextEncode —— 插件的**元数据注入会自动兼容**这种情况，
   查看器能拼出「触发词 + 完整正文」；
3. 出图后，用看图工具打开 PNG，确认「提示词」是完整正文（不是只有触发词）。

### 示例 3：同一角色出一组系列图

**目的**：人物长相固定，只变场景与服装。

1. 选好角色；确认「🔒 角色外观锁定」**开着**（默认开）；
2. `角色联动` 可以保留（服装大类与场景会跟着角色走），也可以关掉让它更随机；
3. 重复 Queue —— 发色 / 发长 / 卷度 / 发态 / 扎法 / 刘海 / 瞳色**每次一样**，
   场景、服装、姿态每次不同；
4. 想固定某一套场景：用「④ 字段微调」把 `scene` 锁死。

**核对方法**：看自检报告里「角色外观锁定」那一行，每项后面标了是「标签」还是「派生」。

### 示例 4：双人 + 分别指定两位角色

1. 设置「⑥ 人物与角色」→ 切到「👥 双人」；
2. 选「角色 A」与「角色 B」（顶部的「选给角色 A / 角色 B」切换目标）；
3. 互动段会**前置**写在提示词最前面，两位角色都**点名**出现；
4. SFW 档走通用互动；NSFW 档**自动**走百合（SFW 档想强制百合就打开「🌸 百合」开关）；
5. 字数上限自动放宽到 1000 字。

### 示例 5：一次出 8 条候选，挑一条

1. 设置「② 随机性质量」→ `批次数` 设为 8；
2. Queue → 第 1 条是主输出（走 `提示词` 端口），第 2–8 条在「候选列表」端口；
3. 把「候选列表」接到一个文本预览节点，或者改用「提示词导出」把 8 条都落盘。

### 示例 6：精确复现某一条

**两条路**：

- **手动**：关掉「每次运行重随机」→ 把 `随机种子` 填成上次的值；
- **一键**：面板「历史」里找到那一条 → 点「↩ 复用此参数」——
  它会把种子、角色、锁定字段、内容强度、人物数量、内容项权重、外观锁定**全部写回控件**，
  并顺手关掉「每次运行重随机」（复用本来就是"要复现那一条"）。

想连"所有字段取值"都一模一样，用「④ 字段微调」的「🔒 锁定当前整套值」。

### 示例 7：用权重控制鞋履与水面波光

- **只想要靴子**：`靴子权重` 保持 1.00，其余五种鞋履权重设 `0`；
  结果只会抽到靴子或「不使用（不写鞋履）」（后者恒为 1.00，不受影响）。
- **完全不要赤脚**：`赤脚权重` = 0。
- **想要明显的水面波光**：`水面反光权重` 调到 `3.00`；
  **完全不要** → 设 `0`。

### 示例 8：让 PNG 元数据带上完整提示词

1. 按示例 2 把链路接好，用**原生 `SaveImage`** 出图；
2. 出图后看自检报告里那行「元数据：已写入提示词（…）」——出现即代表写进去了；
3. 想核对 PNG 里的内容：

```bash
python tools/inspect_png_metadata.py "<出图路径>/xxx.png"
```

输出里会明确写「❌ 没找到」或「✅ 来源 / 长度 / 内容」。

> ⚠️ 如果你的看图工具**只认 A1111 风格的 `parameters` 键**，那它读不到 ——
> 原生 SaveImage 不写这个键，插件也无从写入。用 `--probe` 可以快速判断工具读的是哪个键：
> `python tools/inspect_png_metadata.py "<旧图.png>" --probe "探针.png"`

### 示例 9：把提示词导出归档成 json

1. 接上「提示词导出」节点：`提示词` ← 出题节点的第 1 个端口，
   再把第 2/3/5 个端口（报告 / 槽位 / 元数据）接进它的可选输入；
2. `输出格式` 选 `json`，`保存子目录` 填 `K2V3_archive`；
3. Queue → `output/K2V3_archive/` 下得到含正文 + 报告 + 槽位 + 元数据的完整档案。

适合做数据集、做效果对比、或长期积累素材库。

## 五、常见问题（FAQ）

### 安装与启动

**Q1：重启后搜不到节点？**
① 目录名必须是 `Comfyui-Krea2-Portrait-V3`（别多套一层）；
② 必须**重启 ComfyUI 进程**，刷新网页没用；
③ 看启动日志里有没有这个插件的 Python 报错（通常是文件没拷全）。

**Q2：面板一片空白 / 按钮点了没反应？**
先**刷新浏览器页面**（Ctrl+F5）。若仍不行，检查 `js/` 目录是否完整
（`k2v3_gen.js` / `k2v3_export.js` / `k2v3_prompt_edit.js` 三个文件）。

**Q3：需要装 numpy / PIL 吗？**
不需要。核心出题逻辑只用标准库；只有抓缩略图这类离线工具才可能用到额外包。

### 出题结果

**Q4：为什么提示词里有些内容没出现（比如没有鞋、没有道具）？**
模板填空式生成，很多字段是**概率出现**的。固定的只有镜头 / 人物 / 发型 / 服装主件 /
姿态 / 场景 / 构图等核心项；道具、天气、发饰、袜鞋、纹身、瑕疵等 **28 个补充项**会随机跳过。

**Q5：怎么让某个内容「一定出现」？**
用「④ 字段微调」把对应字段锁成指定值（能锁的 53 个字段里包含这些补充项）。
注意**核心项也能锁**，但 `clothSubCat` / `pose` 这类动态字段不行 —— 它们没有静态候选列表。

**Q6：字数是硬上限吗？超了会怎样？**
单人 ≤600 字、双人 ≤1000 字。超限会**按固定顺序精简**（先砍附加项，再砍次要描写），
报告里会说明砍了什么。你锁定的字段优先级更高，不会被优先砍掉。

**Q7：为什么插件不生成负面提示词？**
v3.19 起取消。负面词表（"不要 XX"）与正文「只写画面里有的」这条口径会互相污染，
两个一起用反而降低出片稳定性。

**Q8：同一角色每次发型都变？**
① 确认「🔒 角色外观锁定」开着（默认开）；② 确认「角色」不是「自动」。
该开关只管外观七项，**不影响服装与场景**，那两项由「角色联动」负责。

**Q9：角色外观锁定的结果能自定义吗？**
可以 —— 用「④ 字段微调」把 `hairColor` / `hairLen` / `eyesColor` 等字段锁成你要的值，
锁定字段优先于外观锁定。

**Q10：双人模式下只出现一个人？**
检查「人物数量」是否真的是「双人」；再看报告里的「人物」一行。
另外单人模式下插件会**主动排除**必须有第二人的内容项（手交 / 乳交 / 足交 / 深喉 / 多人），
这是设计行为。

### 权重与等级

**Q11：权重调到 5.00 为什么「性交」还是不出现？**
因为当前档位够不着它 —— **等级先筛范围、权重再定概率**。
让「性交」出现需要把「内容强度」提到「极端」。

**Q12：整轴权重都乘 2，分布会变吗？**
不会。权重会归一化（概率 = 权重 ÷ 同字段权重和），整轴同乘不改变比例。

**Q13：权重设 0 是真的永不出现吗？**
是。轴级权重、内容项权重、外观细节权重都是这样。

**Q14：「内容权重跟随等级」打开后，我手调的滑块值会丢吗？**
不会。开启时滑块置灰只读并显示档位基准值；关掉立刻回到你之前的手动值。

### 元数据与出图

**Q15：PNG 里提示词不完整 / 只有 LoRA 触发词？**
v3.21 已修。请确认插件版本 ≥ 3.21，并且**用原生 SaveImage 出图**。
若仍不正常，用 `python tools/inspect_png_metadata.py "<图.png>"` 看实际写进去了什么。

**Q16：我的看图工具读不到提示词？**
那多半是它只认 A1111 的 `parameters` 键。用
`python tools/inspect_png_metadata.py "<旧图.png>" --probe "探针.png"`
生成一张带标记文本的探针图，打开看它显示了什么，就能判断它读的是哪个键。

**Q17：插件会替我存图吗？**
**不会。** 从 3.24 起插件只有 3 个节点，没有任何出图 / 存图节点。
出图完全由你自己的 SaveImage / PreviewImage 负责。

### 性能与资源

**Q18：出题卡顿？**
正常应该瞬间完成（纯字符串拼接）。若明显卡顿，检查 `presets/character_pool.json`
是否被误改成超大文件；或把 `去重记忆` 调小。

**Q19：能同时在多个工作流里用吗？**

**Q20：`user_data/` 里的东西会被上传吗？**
不会。插件运行时**不发任何外部请求**。这些文件只在你本机。

## 六、注意事项与限制

1. **输出只有中文**。库内能译的已译成中文，译不出的英文条目已删除；
   唯一豁免是**角色英文原名**（如 `2B`、`Tifa Lockhart`）。
2. **词库的唯一真源是原作者的 HTML 脚本**。改词库要**同时**改 HTML 与 JSON，
   只改 JSON 会在下次导出时被冲回。
3. **控件顺序即兼容性**。新增控件一律追加在末尾；退休控件只撤界面、保留控件位。
   因此升级插件**不需要**改你的既有工作流（除 v3.19 那一次端口变化，见下）。
4. ⚠️ **唯一的例外**：v3.19 取消了「负面提示词」输出端口，导致端口索引整体前移。
   如果你的工作流是在 v3.18 或更早版本上建的，需要把连线往后挪一位（或重建这几个连线）。
   v3.20 起的改动都是末尾追加，不需要处理。
5. **字数上限**：单人 600 / 双人 1000 字。锁定的字段会被保留，精简主要发生在补充项。
6. **角色缩略图不在仓库内**。没有 `thumbs/` 时图鉴退回首字色块，不影响出题。
7. **NSFW 内容**：默认关闭；请自行确认所在地法律法规与使用场景。
8. **不要用真实人物、未成年人**，不要生成非自愿及暴力伤害相关内容。
9. **不要修改节点内部 ID**（`K2V3GeneratorV2` 等）。改 ID 会让所有既有工作流打不开。
